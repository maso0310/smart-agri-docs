關於 SSH 遠端連線

SSH 是管理遠端伺服器、樹莓派、IoT 設備的必備技能。學會 SSH，你就能在任何地方控制你的設備！

什麼是 SSH？

SSH（Secure Shell）是一種加密的網路協定，用於在不安全的網路上安全地進行遠端登入和執行命令。它取代了早期不安全的 Telnet、rlogin 等協定。

SSH 運作原理

加密機制

SSH 使用混合加密系統，結合了對稱加密和非對稱加密的優點：

認證方式

╔══════════════════════════════════════════════════════════════════╗
║  SSH 支援的認證方式                                               ║
╠══════════════════════════════════════════════════════════════════╣
║                                                                  ║
║  1. 密碼認證（Password Authentication）                          ║
║     ├─ 最簡單的方式                                              ║
║     ├─ 密碼透過加密通道傳輸                                      ║
║     └─ 缺點：容易被暴力破解                                      ║
║                                                                  ║
║  2. 公鑰認證（Public Key Authentication）【推薦】                ║
║     ├─ 使用金鑰對（公鑰 + 私鑰）                                 ║
║     ├─ 私鑰保存在客戶端，永不傳輸                                ║
║     ├─ 公鑰放在伺服器上                                          ║
║     └─ 更安全，可免密碼登入                                      ║
║                                                                  ║
║  3. 雙因素認證（Two-Factor Authentication）                      ║
║     ├─ 結合密碼/金鑰 + OTP（一次性密碼）                         ║
║     └─ 最高安全性                                                ║
║                                                                  ║

檔案傳輸

使用 SCP 傳輸檔案

SCP（Secure Copy）使用 SSH 協定進行安全的檔案傳輸。

# 從本機上傳檔案到遠端
scp 本機檔案路徑 使用者@主機:遠端路徑

# 範例：上傳檔案到樹莓派
scp C:\Users\你\Desktop\test.py pi@192.168.1.100:/home/pi/

# 從遠端下載檔案到本機
scp 使用者@主機:遠端檔案路徑 本機路徑

# 範例：從樹莓派下載檔案
scp pi@192.168.1.100:/home/pi/data.txt C:\Users\你\Desktop\

# 傳輸整個資料夾（使用 -r 遞迴）
scp -r 本機資料夾 使用者@主機:遠端路徑

# 範例：上傳整個專案資料夾
scp -r C:\Users\你\project pi@192.168.1.100:/home/pi/

# 指定不同埠號
scp -P 2222 檔案 使用者@主機:路徑

SSH 金鑰認證（免密碼登入）

為什麼使用金鑰認證？

╔══════════════════════════════════════════════════════════════════╗
║  金鑰認證 vs 密碼認證                                             ║
╠══════════════════════════════════════════════════════════════════╣
║                                                                  ║
║  密碼認證的問題：                                                 ║
║  ✗ 每次連線都要輸入密碼，麻煩                                    ║
║  ✗ 密碼可能被暴力破解                                            ║
║  ✗ 密碼可能被釣魚攻擊竊取                                        ║
║  ✗ 難以管理多台伺服器的密碼                                      ║
║                                                                  ║
║  金鑰認證的優點：                                                 ║
║  ✓ 免密碼登入，方便快速                                          ║
║  ✓ 私鑰永不傳輸，無法被竊聽                                      ║
║  ✓ 可以設定私鑰密碼（passphrase）增加安全性                      ║
║  ✓ 可以輕鬆管理多台伺服器的存取權限                              ║
║  ✓ 可以撤銷特定金鑰的存取權限                                    ║
║                                                                  ║
╚══════════════════════════════════════════════════════════════════╝

金鑰認證原理

┌─────────────────────────────────────────────────────────────────┐
│                    公鑰加密原理                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   金鑰對：                                                       │
│   ┌─────────────────┐        ┌─────────────────┐                │
│   │     私鑰        │        │     公鑰        │                │
│   │  (Private Key)  │        │  (Public Key)   │                │
│   │                 │        │                 │                │
│   │  保密！只有你   │  ───►  │  可以公開       │                │
│   │  自己擁有       │  配對   │  放在伺服器上   │                │
│   └─────────────────┘        └─────────────────┘                │
│                                                                 │
│   認證流程：                                                     │
│   1. 伺服器發送隨機挑戰訊息                                      │
│   2. 客戶端用私鑰簽名                                            │
│   3. 伺服器用公鑰驗證簽名                                        │
│   4. 驗證通過，允許登入                                          │
│                                                                 │
│   關鍵：私鑰永遠不會離開你的電腦！                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

產生 SSH 金鑰

# 在你的電腦上執行（Windows PowerShell / macOS Terminal / Linux）

# 產生金鑰對（推薦使用 Ed25519 演算法）
ssh-keygen -t ed25519 -C "your_email@example.com"

# 或使用 RSA（相容性較好）
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# 執行後的互動過程：

│                                                                 │
│ Enter file in which to save the key                             │
│ (C:\Users\你\.ssh\id_ed25519): [按 Enter 使用預設路徑]          │
│                                                                 │
│ Enter passphrase (empty for no passphrase): [輸入密碼或留空]    │
│ Enter same passphrase again: [再輸入一次]                       │
│                                                                 │
│ Your identification has been saved in C:\Users\你\.ssh\id_ed25519│
│ Your public key has been saved in C:\Users\你\.ssh\id_ed25519.pub│

產生的檔案：
┌─────────────────────────────────────────────────────────────────┐
│ C:\Users\你\.ssh\                                               │
│     ├── id_ed25519       ← 私鑰（絕對保密！）                   │
│     └── id_ed25519.pub   ← 公鑰（要複製到伺服器）               │
└─────────────────────────────────────────────────────────────────┘

將公鑰複製到伺服器

# 方法一：使用 ssh-copy-id（Linux/macOS）
ssh-copy-id 使用者@主機

# 方法二：手動複製（Windows 或任何系統）

# 步驟 1：查看公鑰內容
cat ~/.ssh/id_ed25519.pub
# 或在 Windows：
type C:\Users\你\.ssh\id_ed25519.pub

# 輸出類似：
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIxxxxxxxxx your_email@example.com

# 步驟 2：連線到伺服器（這次還需要密碼）
ssh 使用者@主機

# 步驟 3：在伺服器上建立 .ssh 目錄（如果不存在）
mkdir -p ~/.ssh
chmod 700 ~/.ssh

# 步驟 4：將公鑰加入 authorized_keys 檔案
echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIxxxxxxxxx your_email@example.com" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

# 步驟 5：登出並重新連線測試
exit
ssh 使用者@主機
# 這次應該不需要密碼了！

Windows 複製公鑰的簡易方法

# 一行指令完成（在 PowerShell 執行）
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh 使用者@主機 "cat >> .ssh/authorized_keys"

# 或分步驟：

# 1. 複製公鑰內容到剪貼簿
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | Set-Clipboard

# 2. SSH 連線到伺服器
ssh 使用者@主機

# 3. 在伺服器上貼上公鑰
echo "貼上公鑰內容" >> ~/.ssh/authorized_keys

進階設定

SSH 設定檔（簡化連線）

建立 SSH 設定檔可以簡化常用連線的操作。

# 設定檔位置
# Windows: C:\Users\你\.ssh\config
# Linux/macOS: ~/.ssh/config

# 建立或編輯設定檔：
notepad C:\Users\你\.ssh\config    # Windows
nano ~/.ssh/config                  # Linux/macOS

# 設定檔範例：
┌─────────────────────────────────────────────────────────────────┐
│ # 樹莓派                                                        │
│ Host pi                                                         │
│     HostName 192.168.1.100                                      │
│     User pi                                                     │
│     IdentityFile ~/.ssh/id_ed25519                              │
│                                                                 │
│ # 雲端伺服器                                                     │
│ Host myserver                                                   │
│     HostName example.com                                        │
│     User admin                                                  │
│     Port 2222                                                   │
│     IdentityFile ~/.ssh/id_rsa_server                           │
│                                                                 │
│ # 跳板連線（透過中繼伺服器）                                     │
│ Host internal                                                   │
│     HostName 10.0.0.50                                          │
│     User developer                                              │
│     ProxyJump myserver                                          │
│                                                                 │
│ # 所有連線的預設設定                                             │
│ Host *                                                          │
│     ServerAliveInterval 60                                      │
│     ServerAliveCountMax 3                                       │
└─────────────────────────────────────────────────────────────────┘

# 設定後的簡化連線：
ssh pi          # 等同於 ssh pi@192.168.1.100
ssh myserver    # 等同於 ssh -p 2222 admin@example.com
scp file pi:~   # 上傳檔案到樹莓派家目錄

SSH 通道（Port Forwarding）

┌─────────────────────────────────────────────────────────────────┐
│                    SSH 通道類型                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  本地轉發（Local Forwarding）-L                                  │
│  ─────────────────────────────────────────────────────────────  │
│  將遠端服務映射到本機埠                                          │
│                                                                 │
│  ssh -L 本機埠:目標主機:目標埠 使用者@SSH伺服器                  │
│                                                                 │
│  範例：存取遠端 MySQL 資料庫                                     │
│  ssh -L 3306:localhost:3306 pi@192.168.1.100                    │
│  # 現在可以用 localhost:3306 連線到樹莓派的 MySQL                │
│                                                                 │
│  範例：存取內網網頁                                              │
│  ssh -L 8080:192.168.1.50:80 pi@192.168.1.100                   │
│  # 透過樹莓派存取內網 192.168.1.50 的網頁伺服器                  │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  遠端轉發（Remote Forwarding）-R                                 │
│  ─────────────────────────────────────────────────────────────  │
│  讓外部能存取本機服務                                            │
│                                                                 │
│  ssh -R 遠端埠:本機主機:本機埠 使用者@SSH伺服器                  │
│                                                                 │
│  範例：讓伺服器能存取你電腦的開發網站                            │
│  ssh -R 8080:localhost:3000 user@server.com                     │
│  # 伺服器的 8080 埠會轉發到你電腦的 3000 埠                      │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  動態轉發（Dynamic Forwarding）-D                                │
│  ─────────────────────────────────────────────────────────────  │
│  建立 SOCKS 代理伺服器                                          │
│                                                                 │
│  ssh -D 1080 使用者@SSH伺服器                                   │
│  # 本機 1080 埠變成 SOCKS5 代理                                 │
│  # 可以設定瀏覽器使用此代理                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

保持連線不斷線

# 方法一：在連線時加參數
ssh -o ServerAliveInterval=60 使用者@主機

# 方法二：在設定檔中設定（推薦）
# 編輯 ~/.ssh/config
Host *
    ServerAliveInterval 60    # 每 60 秒發送心跳
    ServerAliveCountMax 3     # 3 次沒回應才斷線

# 方法三：伺服器端設定
# 編輯 /etc/ssh/sshd_config
ClientAliveInterval 60
ClientAliveCountMax 3

使用 Fail2Ban 防止暴力破解

# 安裝 Fail2Ban
sudo apt update
sudo apt install fail2ban

# 建立本地設定檔
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local

# 編輯設定
sudo nano /etc/fail2ban/jail.local

# 找到 [sshd] 區段，設定：
[sshd]
enabled = true
port = ssh
filter = sshd
logpath = /var/log/auth.log
maxretry = 3          # 3 次失敗後封鎖
bantime = 3600        # 封鎖 1 小時
findtime = 600        # 在 10 分鐘內

# 啟動服務
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# 查看封鎖狀態
sudo fail2ban-client status sshd

常見問題排除

問題：Connection refused

症狀：ssh: connect to host 192.168.1.100 port 22: Connection refused

可能原因與解決方案：
┌─────────────────────────────────────────────────────────────────┐
│ 1. SSH 服務未啟動                                               │
│    解決：在伺服器上執行 sudo systemctl start sshd               │
│                                                                 │
│ 2. SSH 服務未安裝                                               │
│    解決：sudo apt install openssh-server                        │
│                                                                 │
│ 3. 防火牆阻擋                                                    │
│    解決：sudo ufw allow 22                                      │
│    或：sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT       │
│                                                                 │
│ 4. SSH 使用非預設埠                                             │
│    解決：ssh -p 埠號 使用者@主機                                │
│                                                                 │
│ 5. IP 位址錯誤                                                  │
│    解決：確認目標主機的正確 IP 位址                             │
└─────────────────────────────────────────────────────────────────┘

問題：Connection timed out

症狀：ssh: connect to host 192.168.1.100 port 22: Connection timed out

可能原因與解決方案：
┌─────────────────────────────────────────────────────────────────┐
│ 1. 網路不通                                                     │
│    測試：ping 192.168.1.100                                     │
│    解決：檢查網路連線、路由設定                                  │
│                                                                 │
│ 2. 目標主機未開機                                               │
│    解決：確認主機已開機並連上網路                               │
│                                                                 │
│ 3. 不在同一網段                                                 │
│    解決：確認 IP 位址和子網路遮罩設定正確                       │
│                                                                 │
│ 4. 路由器/防火牆阻擋                                            │
│    解決：檢查中間設備的防火牆規則                               │
└─────────────────────────────────────────────────────────────────┘

問題：Permission denied

症狀：Permission denied (publickey,password)

可能原因與解決方案：
┌─────────────────────────────────────────────────────────────────┐
│ 1. 密碼錯誤                                                     │
│    解決：確認密碼正確，注意大小寫                               │
│                                                                 │
│ 2. 使用者名稱錯誤                                               │
│    解決：確認正確的使用者名稱                                   │
│                                                                 │
│ 3. 金鑰權限問題                                                 │
│    解決：chmod 600 ~/.ssh/id_ed25519                            │
│          chmod 700 ~/.ssh                                       │
│                                                                 │
│ 4. 公鑰未正確加入伺服器                                         │
│    解決：檢查 ~/.ssh/authorized_keys 內容                       │
│                                                                 │
│ 5. 伺服器 authorized_keys 權限問題                              │
│    解決：chmod 600 ~/.ssh/authorized_keys                       │
│          chmod 700 ~/.ssh                                       │
│                                                                 │
│ 6. SELinux 問題（某些 Linux 發行版）                            │
│    解決：restorecon -Rv ~/.ssh                                  │
└─────────────────────────────────────────────────────────────────┘

問題：Host key verification failed

症狀：
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

原因：伺服器的主機金鑰與之前記錄的不同
（可能是伺服器重裝、IP 被重新分配、或被中間人攻擊）

解決方案：
┌─────────────────────────────────────────────────────────────────┐
│ 如果確定是正常變更（如重裝系統）：                               │
│                                                                 │
│ 方法一：刪除舊的主機金鑰                                        │
│ ssh-keygen -R 192.168.1.100                                     │
│                                                                 │
│ 方法二：手動編輯 known_hosts 檔案                               │
│ 刪除 ~/.ssh/known_hosts 中對應 IP 的那一行                      │
│                                                                 │
│ 然後重新連線，會提示接受新的主機金鑰                            │
│                                                                 │
│ ⚠️ 警告：如果不確定原因，請勿輕易接受新金鑰！                   │
│    這可能是中間人攻擊的跡象                                      │
└─────────────────────────────────────────────────────────────────┘

問題：連線很慢

症狀：SSH 連線需要很長時間才能建立

可能原因與解決方案：
┌─────────────────────────────────────────────────────────────────┐
│ 1. DNS 反向查詢超時                                             │
│    解決：在伺服器 /etc/ssh/sshd_config 加入：                   │
│          UseDNS no                                              │
│                                                                 │
│ 2. GSSAPI 認證超時                                              │
│    解決：連線時加參數：                                         │
│          ssh -o GSSAPIAuthentication=no 使用者@主機             │
│    或在設定檔加入：                                              │
│          GSSAPIAuthentication no                                │
│                                                                 │
│ 3. 網路品質差                                                   │
│    測試：ping 主機 查看延遲                                     │
│    解決：檢查網路連線品質                                       │
└─────────────────────────────────────────────────────────────────┘

ssh -R 8080:localhost:80 user@host   遠端轉發
