第六組：網路控制組 操作手冊

任務說明

本組負責智慧溫室的物聯網連線功能，包含： - 使用 ESP-01 WiFi 模組連接網路 - 透過 MQTT 協定發送感測器資料 - 將模擬資料發送到公開 MQTT Broker - 在手機上使用 IoT MQTT Panel 即時查看資料

這是將溫室連上雲端的關鍵技術！

ESP-01 模組介紹

ESP-01 腳位圖

ESP-01 正面（天線朝上）：
┌──────────────────────┐
│   ▄▄▄▄▄▄▄▄▄▄▄        │
│   █ ESP8266 █ 天線   │
│   ▀▀▀▀▀▀▀▀▀▀▀        │
│                      │
│  ● GND    ● GPIO2    │  ← 下排
│  ● GPIO0  ● GPIO1/TX │
│                      │
│  ● RX     ● CH_PD    │  ← 上排
│  ● RST    ● VCC      │
│                      │
└──────────────────────┘

腳位說明：
- VCC：電源 3.3V（絕對不可接 5V！）
- GND：接地
- TX：傳送（GPIO1）
- RX：接收（GPIO3）
- CH_PD：啟用腳（需接高電平）
- RST：重置腳（低電平重置）
- GPIO0：模式選擇（燒錄時接 GND）
- GPIO2：通用 IO

工作模式

ESP-01 開機模式：

1. 正常運行模式：
   - GPIO0 = HIGH（浮空或接 VCC）
   - 開機後執行 Flash 中的程式

2. 燒錄模式：
   - GPIO0 = LOW（接 GND）
   - 開機進入燒錄狀態
   - 上傳程式後需重新接電

ESP-01 燒錄器與轉接頭介紹

ESP-01 模組本身沒有 USB 介面，需要透過燒錄器或轉接頭來上傳程式。以下介紹常見的幾種方式：

方式一：USB 燒錄器（最推薦）

ESP-01 USB 燒錄器外觀：
┌─────────────────────────────────────┐
│                                     │
│   ┌───────────────┐                 │
│   │   ESP-01      │  ← ESP-01 插槽  │
│   │   插入這裡    │                 │
│   └───────────────┘                 │
│                                     │
│   [UART/FLASH] ← 模式切換開關       │
│                                     │
│   ═══════════                       │
│   USB 接頭                          │
└─────────────────────────────────────┘

常見型號：
1. CH340 晶片版（最常見、便宜）
2. CP2102 晶片版（穩定性較好）

USB 燒錄器使用方法

步驟 操作說明
1. 插入 ESP-01 注意方向！天線朝外，晶片朝內
2. 切換到燒錄模式 將開關撥到「UART」或「PROG」位置
3. 插入電腦 USB 等待驅動程式安裝完成
4. 選擇 COM Port 在 Arduino IDE 的「工具」→「序列埠」選擇
5. 上傳程式 點擊「上傳」按鈕
6. 切換到運行模式 上傳完成後，將開關撥到「FLASH」或「RUN」位置
7. 重新插拔 拔掉再插回 USB，程式開始執行

搭配 USB 轉 TTL 模組使用

USB 轉 TTL 模組（例如 FT232、PL2303、CH340）：
┌─────────────────┐
│  USB 轉 TTL     │
│  ┌───────────┐  │
│  │ VCC  3.3V │──┼──→ ESP-01 VCC（注意！必須是 3.3V）
│  │ GND       │──┼──→ ESP-01 GND
│  │ TXD       │──┼──→ ESP-01 RX（交叉連接！）
│  │ RXD       │──┼──→ ESP-01 TX（交叉連接！）
│  └───────────┘  │
│  ════════════   │
│  USB 接頭       │
└─────────────────┘

重要：TX 接 RX，RX 接 TX（交叉連接）

方式三：Arduino 當作燒錄器（進階）

使用 Arduino UNO 作為 USB 轉 TTL：

Arduino UNO          ESP-01
┌──────────┐        ┌──────────┐
│ 3.3V     │───────→│ VCC      │
│ GND      │───────→│ GND      │
│ TX (D1)  │───────→│ RX       │
│ RX (D0)  │───────→│ TX       │
│ GND      │───────→│ GPIO0    │ ← 燒錄時接 GND
│ 3.3V     │───────→│ CH_PD    │
│ RESET    │───────→│ GND      │ ← 將 Arduino 重置腳接地
└──────────┘        └──────────┘

注意：Arduino RESET 接 GND 是為了讓 Arduino
本身不執行程式，只當作 USB 轉 TTL 使用

MQTT 基礎知識

什麼是 MQTT？

MQTT (Message Queuing Telemetry Transport)
- 輕量級的訊息傳遞協定
- 專為物聯網設計
- 低頻寬、低耗電
- 發布/訂閱模式

架構：
┌─────────────────────────────────────┐
│           MQTT Broker               │
│      (訊息中轉伺服器)                │
└─────────────────────────────────────┘
         ↑                 ↓
    發布訊息            訂閱訊息
         ↑                 ↓
┌─────────────┐    ┌─────────────┐
│   ESP-01    │    │   手機 APP   │
│  (發布者)   │    │  (訂閱者)    │
└─────────────┘    └─────────────┘

主題（Topic）設計

主題命名範例：
greenhouse/group6/temperature    ← 溫度
greenhouse/group6/humidity       ← 濕度
greenhouse/group6/soil          ← 土壤濕度
greenhouse/group6/light         ← 光線
greenhouse/group6/status        ← 系統狀態

建議：使用唯一的名稱避免與他人衝突
例如：greenhouse/學號或名字/...

常見問題

Q1：無法上傳程式

  • 確認 ESP-01 進入燒錄模式（GPIO0 接 GND）
  • 檢查 COM Port 選擇正確
  • 嘗試降低上傳速度至 115200
  • 確認驅動程式安裝（CH340 或 CP2102）

Q2：WiFi 連不上

  • 確認 SSID 和密碼正確（區分大小寫）
  • 確認 WiFi 是 2.4GHz（ESP-01 不支援 5GHz）
  • 確認路由器允許新裝置連線
  • 嘗試靠近路由器

Q3：MQTT 連線失敗

  • 確認 Broker 位址正確
  • 確認網路可以對外連線
  • 嘗試其他 Broker
  • 檢查防火牆設定

Q4：手機收不到資料

  • 確認訂閱的主題與發布的主題相同
  • 確認 ESP-01 有成功發布（看序列埠）
  • 確認手機網路正常
  • 嘗試重啟 APP

知識補充

MQTT QoS 等級

QoS (Quality of Service) 服務品質：

QoS 0 - 最多一次
- 不保證送達
- 最快、最省資源
- 適合：可以遺失的資料

QoS 1 - 至少一次
- 保證送達
- 可能重複
- 適合：重要但可重複的資料

QoS 2 - 恰好一次
- 保證送達且不重複
- 最慢、最耗資源
- 適合：不可重複的命令

ESP-01 省電技巧

1. Deep Sleep 模式：
   - 最低功耗 ~20μA
   - 需要連接 RST 和 GPIO16
   - ESP-01 不方便使用

2. Light Sleep 模式：
   - WiFi 保持連線
   - 功耗約 0.9mA
   - 可被定時器或中斷喚醒

3. Modem Sleep 模式：
   - CPU 正常運作
   - WiFi 模組休眠
   - 約 15mA

與其他組別的整合

本組是連接各組與雲端的橋樑：

  • 第一組（光線）→ 發送光線強度
  • 第二組（溫溼度）→ 發送溫度與濕度
  • 第三組（土壤）→ 發送土壤濕度
  • 第四組（顯示）→ 接收資料顯示
  • 第五組（遙控）→ 接收遠端控制指令

最終目標：手機可以遠端監控整個溫室！
