關於 MQTT

什麼是 MQTT？

MQTT (Message Queuing Telemetry Transport) 是一種輕量級的訊息傳輸協定，專門為物聯網 (IoT) 設計。

一句話解釋

MQTT 就像一個「廣播電台系統」：有人發送訊息（廣播），有人收聽訊息（收音機），而電台（伺服器）負責轉發。

為什麼需要 MQTT？

傳統 HTTP 的問題

感測器 A ──HTTP請求──→ 伺服器 ──HTTP請求──→ 手機 App
感測器 B ──HTTP請求──→ 伺服器 ──HTTP請求──→ 手機 App
感測器 C ──HTTP請求──→ 伺服器 ──HTTP請求──→ 手機 App

問題：

  • 每次都要建立新連線，耗電耗流量
  • 伺服器要主動通知手機很麻煩
  • 連線數量多時伺服器負擔大

MQTT 的解決方案

感測器 A ─┐                    ┌─ 手機 App
感測器 B ─┼── MQTT Broker ────┼─ 電腦
感測器 C ─┘   (中央轉發站)     └─ 其他裝置

優點：

  • 保持長連線，省電省流量
  • 訊息即時推送
  • 一對多、多對多通訊輕鬆實現

核心概念

1. Broker（代理伺服器）

Broker 就像「郵局」或「廣播電台」

  • 負責接收所有訊息
  • 負責轉發訊息給訂閱者
  • 不需要自己架設，可以用公開的 Broker
常用公開 Broker：
- broker.hivemq.com (免費、穩定)
- test.mosquitto.org (測試用)
- broker.emqx.io (免費)

2. Client（客戶端）

任何連接到 Broker 的裝置都是 Client：

  • Arduino + ESP8266/ESP32
  • 手機 App
  • 電腦程式
  • 樹莓派

3. Topic（主題）

Topic 就像「頻道」或「郵件地址」

訊息透過 Topic 來分類和路由：

greenhouse/temperature    ← 溫度數據
greenhouse/humidity       ← 濕度數據
greenhouse/control/fan    ← 風扇控制
greenhouse/control/pump   ← 水泵控制

Topic 的階層結構

home/
├── livingroom/
│   ├── temperature
│   ├── humidity
│   └── light
├── bedroom/
│   ├── temperature
│   └── ac/status
└── garden/
    ├── soil/moisture
    └── sprinkler/control

萬用字元 (Wildcard)

符號 意義 範例
+ 單層萬用 home/+/temperature 匹配所有房間的溫度
# 多層萬用 home/# 匹配 home 下所有主題

4. Publish（發布）

發布就像「發送廣播」

# 發布溫度數據到 topic
client.publish("greenhouse/temperature", "25.5")

5. Subscribe（訂閱）

訂閱就像「收聽頻道」

# 訂閱溫度主題，收到訊息時會觸發 callback
client.subscribe("greenhouse/temperature")

QoS（服務品質等級）

MQTT 提供三種訊息傳遞保證：

QoS 名稱 說明 適用情境
0 最多一次 發送後不管，可能丟失 感測器頻繁更新的數據
1 至少一次 確保送達，可能重複 一般控制指令
2 剛好一次 確保送達且不重複 重要指令（如付款）

選擇建議

  • 感測器數據：QoS 0（丟一兩筆沒關係）
  • 控制指令：QoS 1（確保送達）
  • 重要操作：QoS 2（不能重複執行）

MQTT vs HTTP 比較

特性 MQTT HTTP
連線方式 長連線 (保持連接) 短連線 (每次重連)
通訊模式 發布/訂閱 請求/回應
訊息大小 極小 (2 bytes 起) 較大 (Headers 很多)
即時性 即時推送 需要輪詢
耗電量 低 高
適用場景 物聯網、即時通訊 網頁、API
一對多通訊 原生支援 需要額外實作

什麼時候用 MQTT？

  • 設備資源有限（Arduino、ESP8266）
  • 需要即時通知
  • 一對多或多對多通訊
  • 網路不穩定的環境

什麼時候用 HTTP？

  • 需要請求-回應模式
  • 與現有網頁服務整合
  • 單次資料查詢

實際應用範例

範例 1：Python 發布者 (Publisher)

import paho.mqtt.client as mqtt
import time
import random

# 連接設定
BROKER = "broker.hivemq.com"
PORT = 1883
TOPIC = "classroom/temperature"

# 建立客戶端
client = mqtt.Client()
client.connect(BROKER, PORT)

# 每 5 秒發送一次溫度
while True:
    temperature = round(random.uniform(20, 30), 1)
    client.publish(TOPIC, temperature)
    print(f"發布: {temperature}°C")
    time.sleep(5)

範例 2：Python 訂閱者 (Subscriber)

import paho.mqtt.client as mqtt

BROKER = "broker.hivemq.com"
PORT = 1883
TOPIC = "classroom/temperature"

# 收到訊息時的回調函數
def on_message(client, userdata, msg):
    print(f"收到 [{msg.topic}]: {msg.payload.decode()}")

# 連接成功時的回調
def on_connect(client, userdata, flags, rc):
    print("已連接到 Broker")
    client.subscribe(TOPIC)
    print(f"已訂閱: {TOPIC}")

# 建立客戶端
client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

# 連接並開始監聽
client.connect(BROKER, PORT)
client.loop_forever()

範例 3：Arduino + ESP8266 發布感測器數據

#include <ESP8266WiFi.h>
#include <PubSubClient.h>

// WiFi 設定
const char* ssid = "你的WiFi名稱";
const char* password = "你的WiFi密碼";

// MQTT 設定
const char* mqtt_server = "broker.hivemq.com";
const int mqtt_port = 1883;

WiFiClient espClient;
PubSubClient client(espClient);

void setup() {
  Serial.begin(9600);

  // 連接 WiFi
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("WiFi 已連接");

  // 連接 MQTT
  client.setServer(mqtt_server, mqtt_port);
}

void loop() {
  if (!client.connected()) {
    reconnect();
  }
  client.loop();

  // 每 5 秒發送一次
  static unsigned long lastMsg = 0;
  if (millis() - lastMsg > 5000) {
    lastMsg = millis();

    // 發布溫度
    float temp = 25.5;  // 實際應從感測器讀取
    char msg[10];
    dtostrf(temp, 4, 1, msg);
    client.publish("greenhouse/temperature", msg);
    Serial.printf("發布溫度: %s\n", msg);
  }
}

void reconnect() {
  while (!client.connected()) {
    Serial.print("連接 MQTT...");
    if (client.connect("ESP8266Client")) {
      Serial.println("已連接");
    } else {
      Serial.print("失敗, rc=");
      Serial.println(client.state());
      delay(5000);
    }
  }
}

安全性考量

1. 使用帳號密碼

client.username_pw_set("username", "password")
client.connect(BROKER, PORT)

2. 使用 TLS/SSL 加密

client.tls_set()  # 使用預設 CA
client.connect(BROKER, 8883)  # TLS 通常用 port 8883

3. Topic 權限控制

常見問題

Q1: 訊息會保留嗎？

A: 預設不會。但可以設定 Retained Message，新訂閱者會收到最後一則保留訊息。

client.publish("topic", "message", retain=True)

Q2: 斷線後訊息會丟失嗎？

A: 看 QoS 設定和 Clean Session 設定。設定 clean_session=False 可以保留離線訊息。

Q3: 一個 Topic 可以有多少訂閱者？

A: 理論上沒有限制，取決於 Broker 的效能。

Q4: MQTT 可以傳送檔案嗎？

A: 技術上可以（用 Base64 編碼），但不建議。MQTT 設計用於小訊息。

總結

MQTT 核心概念口訣

Broker 是郵局，負責收發信
Topic 是地址，決定寄到哪
Publish 是寄信，把訊息發出
Subscribe 是訂閱，等待信送來

何時選擇 MQTT

  • ✅ 物聯網設備通訊
  • ✅ 即時數據推送
  • ✅ 多設備協作
  • ✅ 資源受限的環境
  • ❌ 需要請求-回應模式
  • ❌ 傳輸大型檔案
